# otp-frontend

Frontend of Ordena tu Pyme (cash flow and accounts payable for Chilean SMEs), the client of [otp-api](https://github.com/enzobriones/otp-api). Next.js 16 with Server Components and Server Actions, shadcn/ui (Base UI) and Tailwind 4, pnpm.

## Commands

```bash
pnpm install
cp .env.example .env.local   # API_BASE_URL → the API, including /v1
pnpm dev                     # frontend on :3001 (run the API separately)
pnpm lint
pnpm typecheck
pnpm test
pnpm format
pnpm build
```

CI runs: `pnpm lint`, `pnpm typecheck`, `pnpm exec prettier --check "**/*.{ts,tsx}"`, `pnpm test`, `pnpm build`.

## Structure (under `src/`)

- `app/`: routes, layouts, `globals.css`
- `components/`: UI; `components/ui/` is generated by shadcn (do not hand-edit, exempt from lint rules)
- `server/<module>/`: Server Actions (`<module>.actions.ts`) and server-only API access (`<module>.api.ts`)
- `constants/*.constants.ts`: labels, form fields, limits
- `utils/*.utils.ts`: pure helpers (response validation, form parsing, formatting)
- `types/*.types.ts`: types per module
- `test/` (repo root): `node:test` specs, `*.test.ts`

## Conventions

- The browser never calls the API: reads and writes go through Server Components and Server Actions. `API_BASE_URL` is not `NEXT_PUBLIC_`.
- Arrow functions only (enforced by ESLint). Named exports, except Next special files (`page`, `layout`, ...).
- Prettier: no semicolons, double quotes, 80 columns, Tailwind class sorting.
- User-facing text in Spanish; code in English.
- The session is a JWT in an httpOnly cookie set by the API; never read or store it in client JavaScript.

## Deploy

Railway project `ordena-tu-pyme`, service `frontend`, deployed from GitHub after CI passes (Wait for CI). Config lives in the Railway dashboard.

- `production` ← `main`, `staging` ← `develop`.
- Build `pnpm build`, start `pnpm start` (Next takes `PORT`).
- Variables: `NODE_ENV=production` and `API_BASE_URL=http://${{api.RAILWAY_PRIVATE_DOMAIN}}:${{api.PORT}}/v1` (the API of the same environment, over the private network).

## Git

- Work on `feat/<slice>` off an up-to-date `develop`, open a PR to `develop`, merge once CI passes (`gh pr merge <n> --merge --delete-branch`). Production releases are a PR from `develop` to `main`.
- Conventional Commits with scope: `feat(web): ...`, `fix(web): ...`, `chore(web): ...`, `docs: ...`.
- Commits and PR descriptions have no `Co-Authored-By` line and no tool signature.
